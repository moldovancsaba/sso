## 5. Tokenisation map

Two facts govern every row. `createPublicBrandTheme` emits no `--gds-*` variable, and `GdsProvider` injects only `theme.other.gdsCssVariables` (`GDS:packages/gds-theme/src/theme.ts:285-308`, `GDS:packages/gds-theme/src/GdsProvider.tsx:78-90`), so sso gets only what `styles.css` defines statically: the `--gds-vibe-*` defaults, the structural role variables (`--gds-bg-*`, `--gds-text-*`, `--gds-border-card`), the overlay surface and the motion durations. The axis tokens (`--gds-space-*`, `--gds-radius-*`, `--gds-elevation-*`), `--gds-state-*`, `--gds-brand-*` and `--gds-focus-ring` reach a page only when a theme preset is active, which is the DoneIsBetter SSO preset [#846 Theme: DoneIsBetter SSO brand preset - register a base-composed blue identity lane with declared shape and elevation axes](https://github.com/sovereignsquad/general-design-system/issues/846). Components that read them carry fallbacks.

## 9. Outside GDS

| # | Severity | What is wrong | Where | Fix |
|---|---|---|---|---|
| 1 | high | The consent page trusts an unsigned request. It base64-decodes the `request` query parameter (`pages/api/oauth/authorize.js:298-313` issues it with no signature) and renders `client_name`, `client_logo` and `client_homepage` from it; the server never sees those fields, and its re-validation covers only `client_id`, `redirect_uri`, `scope` and the PKCE parameters (`lib/oauth/authorizationValidation.mjs:29-79`), so a crafted link can show any client identity above a real `client_id`.
